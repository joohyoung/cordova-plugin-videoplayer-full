# version-up

이 저장소가 배포하는 **Cordova 플러그인 버전**을 올린다. Cordova CLI 버전이나 플랫폼(`cordova-ios`, `cordova-android`) 버전이 아니다.

## 버전 소스 지정

**이 절이 이 저장소의 버전 소스 지정이다.** 버전 상향을 이 스킬에 위임하는 호출자(예: 릴리스 절차)가 버전 값을 읽어야 할 때는 아래 두 곳만 읽는다. 절차 단계 번호가 아니라 이 절이 지정의 근거다.

| 버전 소스 | 위치 |
|---|---|
| `package.json` | 최상위 객체의 `version` 필드 |
| `plugin.xml` | 루트 `<plugin>` 요소의 `version` 속성 |

두 값은 항상 같아야 하며, 다르면 이 스킬은 2단계에서 파일을 고치지 않고 중단한다.

**`plugin.xml`에는 `version`이 두 군데 있다.** 1행의 XML 선언 `<?xml version="1.0" encoding="UTF-8"?>`에도 `version` 속성이 있는데, 이것은 **XML 사양의 버전이며 절대 건드리지 않는다.** 버전 소스는 루트 `<plugin>` 요소의 것 하나뿐이다. "파일에서 처음 나오는 `version=`" 같은 어림으로 찾으면 XML 선언을 고쳐 파일을 깨뜨린다.

버전 파일을 실제로 고치는 것은 아래 절차의 **5단계**다. 버전 소스만 읽고 파일은 고치지 않으려는 호출자는 1·2단계까지만 수행한다.

## 버전 형식

- 안정 버전 SemVer `M.m.p` 만 받는다 (예: `1.0.7`).
- `M`, `m`, `p`는 각각 0 이상의 정수다. 앞자리 0을 붙인 값(`1.0.07`)은 받지 않는다.
- 프리릴리스·빌드 메타데이터(`-beta.1`, `+build.5`)는 이 스킬에서 받지 않는다.
- 앱 전용 4자리 빌드 번호, `android-versionCode`, `ios-CFBundleVersion`은 이 저장소에 없으며 이 스킬이 만들지 않는다.

## 절차

아래 순서를 그대로 따른다. 각 단계의 성패는 출력 문구가 아니라 **종료 코드**로 가린다. 어느 단계에서 중단하든 그 시점까지 파일을 수정하지 않았으면 아무것도 수정하지 않은 상태로 끝낸다.

### 1. 현재 버전 읽기

저장소 루트에서 아래 명령을 실행한다. 두 원본을 함께 읽어 `package.json`과 `plugin.xml` 값을 탭으로 구분해 낸다.

```bash
node -e '
const fs=require("fs");
function fail(m){console.error(m);process.exit(1);}
let p;
try{p=JSON.parse(fs.readFileSync("package.json","utf8"));}catch(e){fail("package.json 읽기/파싱 실패: "+e.message);}
const pv=p.version;
if(typeof pv!=="string"||pv==="")fail("package.json의 최상위 version 필드가 비었거나 문자열이 아닙니다");
let x;
try{x=fs.readFileSync("plugin.xml","utf8");}catch(e){fail("plugin.xml 읽기 실패: "+e.message);}
const t=x.replace(/<!--[\s\S]*?-->/g,"").match(/<plugin(?=[\s>\/])[^>]*>/);
if(!t)fail("plugin.xml에서 루트 <plugin> 여는 태그를 찾지 못했습니다");
const re=/\s([A-Za-z_:][-\w:.]*)\s*=\s*(?:"([^"]*)"|\x27([^\x27]*)\x27)/g;
let m,xv;
while((m=re.exec(t[0]))!==null){if(m[1]==="version"){xv=m[2]!==undefined?m[2]:m[3];break;}}
if(xv===undefined)fail("plugin.xml 루트 <plugin>에 version 속성이 없습니다");
if(xv==="")fail("plugin.xml 루트 <plugin>의 version 속성이 비어 있습니다");
console.log("package.json\t"+pv);
console.log("plugin.xml\t"+xv);
'
```

이 명령이 지키는 것:

- **주석과 중첩 태그를 먼저 걷어 낸다.** XML 주석을 제거한 뒤 첫 `<plugin` **여는 태그 안에서만** `version`을 찾는다. 주석 처리된 `<!-- <plugin version="0.0.1"> -->`나 중첩된 `<plugin version="9.9.9"/>`의 값을 루트 값으로 잘못 읽지 않으며, 루트 태그에 `version`이 없으면 다른 태그로 넘어가지 않고 종료 코드 1로 끝난다.
- **속성을 앞에서부터 하나씩 순회해 이름이 정확히 `version`인 것만 고른다.** 태그 문자열에서 `version=`을 곧바로 찾으면 다른 속성의 **값 안에 들어 있는** 문자열을 집는다 — 예컨대 `<plugin id="a version=\x279.9.9\x27" version="1.0.6">`에서 `9.9.9`를 루트 버전으로 읽는다(실측). XML은 큰따옴표 값 안의 작은따옴표를 허용하므로 유효한 파일에서 일어날 수 있다. 속성 쌍을 통째로 소비하며 순회하면 그 안쪽은 검사 대상이 되지 않는다.
- **큰따옴표와 작은따옴표를 모두 인식한다.** XML은 둘 다 허용하므로 어느 쪽이든 읽는다(스크립트를 작은따옴표 셸 문자열로 감쌀 수 있도록 정규식 안에서는 `\x27`로 적었다).
- **빈 값을 성공으로 읽지 않는다.** `version` 필드가 없거나(`undefined`), `null`이거나, 빈 문자열이거나, `version=""` 빈 속성이면 모두 종료 코드 1로 끝난다. 종료 코드만 보는 판정이 빈 출력을 정상으로 오독하지 않게 하려는 것이다.
- **스크립트를 작은따옴표로 감싼다.** 본문에 `require("fs")`, `"utf8"`, `"package.json"`처럼 큰따옴표가 여러 개 들어 있어, 큰따옴표로 감싸면 문자열이 그 자리에서 조기 종료되고 나머지가 셸 구문으로 읽혀 `syntax error near unexpected token`으로 끝난다(실측). 본문에 작은따옴표가 하나도 없도록 XML의 작은따옴표를 `\x27`로 적어 둔 것이 이 래핑을 성립시킨다. 이 스킬은 서로 다른 에이전트에서 실행되므로 셸 이스케이프에 의존하지 않는다.

처리:

- **비정상 종료하면** 그 출력을 그대로 보고하고 **파일을 수정하지 않은 채 중단한다.**
- 읽은 두 값을 각각 `{현재-package}`, `{현재-plugin}`으로 기록한다. 이 둘은 **2단계에서 값이 다를 때 어느 파일이 무엇인지 보고하는 데만 쓴다** — 이후 단계는 두 값이 같음을 확인한 뒤의 단일 값 `{현재버전}`만 쓰며, 2·4단계 명령은 두 파일을 스스로 다시 읽는다.

### 2. 두 원본의 현재 버전 일치·형식 확인

1단계와 같은 방식으로 두 값을 다시 읽어 비교와 형식 검증까지 한 번에 수행한다. 1단계 스크립트 끝의 두 `console.log` 줄을 아래로 바꿔 실행한다. 아래는 그 자리에 넣을 JavaScript 조각이며 셸에 그대로 붙여 실행하는 명령이 아니다.

```js
const SEMVER=/^(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$/;
if(pv!==xv)fail("두 원본의 현재 버전이 다릅니다 (package.json="+pv+", plugin.xml="+xv+"). 파일을 수정하지 않고 중단합니다");
if(!SEMVER.test(pv))fail("현재 버전 "+pv+"은(는) 안정 버전 SemVer M.m.p가 아닙니다. 두 파일의 현재 값을 먼저 바로잡으십시오");
console.log(pv);
```

- **두 값이 다르면** 파일을 수정하지 않고 두 값과 각 파일 경로를 보고한 뒤 중단한다. 어느 쪽이 옳은지 이 스킬이 추측해 맞추지 않는다.
- **현재 버전이 `M.m.p` 형식이 아니면** 파일을 수정하지 않고 중단한다. 두 파일이 똑같이 `1.0.6-beta.1`처럼 적혀 있어도 여기서 걸린다 — 3단계의 patch/minor/major 후보 계산이 `M.m.p`를 전제하므로 형식이 어긋난 값에서는 후보가 정의되지 않고, 그대로 두면 4단계가 원인을 알기 어려운 실패로 끝난다. **이 검사를 제거하지 않는다** — 4단계의 `!(cmp>0)` 판정이 `NaN`을 실패로 떨어뜨리는 것과는 별개의 이유로 필요하다.
- 두 검사를 지나면 그 값을 `{현재버전}`으로 기록하고 다음 단계로 간다.

### 3. 새 버전 정하기

호출 형태에 따라 세 갈래로 갈린다. **위에서부터 차례로 보고 처음 맞는 갈래를 쓴다.**

1. **증가 단위(`major` / `minor` / `patch`)를 받았으면** 그 단위를 **그대로 4단계에 넘긴다.** 계산은 4단계 명령이 하므로 이 자리에서 손으로 계산해 버전 값으로 바꾸지 않는다 — 손계산이 틀려도 4단계는 "현재보다 큰 SemVer"만 보므로 잘못된 값이 통과한다(예: `1.0.9`에 minor를 잘못 적용한 `1.1.9`). **이 갈래에서는 후보를 제시하지도, 입력을 기다리지도 않는다.**
   - 이 갈래가 필요한 이유: 저장소 릴리스 절차(`/gh:changelog`)가 증가 단위를 스스로 결정한 뒤 이 스킬에 그 단위를 넘겨 호출한다. 그 호출은 사람이 답할 자리가 없으므로, 단위를 받으면 후보 제시 없이 곧바로 4단계로 넘어가야 한다.
2. **구체적인 새 버전 값을 받았으면** 그 값을 `{새버전}`으로 쓰고 4단계로 간다.
3. **아무것도 받지 않았으면** **4단계의 명령을 인자 없이** 실행해 세 후보를 계산하고, 그 출력을 보여 준 뒤 어느 것으로 올릴지(또는 직접 입력할 값이 있는지) 입력받는다. 받은 답을 `{새버전}` 또는 증가 단위로 삼아 4단계로 간다.
   - 그 명령은 아래 4단계에 있다. **조합 방법도 그 자리에 적혀 있다** — 1단계 스크립트 끝의 두 `console.log` 줄을 4단계 코드 블록으로 바꿔 `node -e '…'`로 실행하되, 이 갈래에서는 인자를 붙이지 않는다.
   - **이 인자 없는 호출은 후보 산출일 뿐 검증이 아니다.** 여러 줄 목록을 내고 종료 코드 0으로 끝나므로, 그 출력을 `{새버전}`으로 기록하거나 이것으로 4단계를 대신해 5단계로 넘어가지 않는다.

**참고**: 4단계 명령이 후보를 계산할 때 쓰는 식은 다음과 같다. **이 표를 손으로 적용해 버전 값을 만들지 않는다** — 계산은 언제나 4단계 명령이 한다.

| 단위 | 계산 | `2.3.4` 기준 예시 |
|---|---|---|
| patch | `M.m.(p+1)` | `2.3.5` |
| minor | `M.(m+1).0` | `2.4.0` |
| major | `(M+1).0.0` | `3.0.0` |

- 후보 제시와 입력 수집은 실행 중인 에이전트가 쓸 수 있는 아무 방식으로나 한다. 특정 도구 이름에 의존하지 않는다.
- **3번 갈래에서** 대화형 입력이 불가능한 실행 환경이면(무인 실행, 루프 실행 등) 임의로 고르지 말고 계산한 후보만 출력한 뒤 중단한다. 같은 갈래에서 입력을 요청했으나 받지 못한 경우도 같다. **1·2번 갈래는 받은 값으로 그대로 진행하므로 이 항이 걸리지 않는다.**

### 4. 새 버전 검증

3단계에서 정한 값을 아래 명령으로 검증한다. **이 단계는 인자를 반드시 하나 넘긴다** — `major`·`minor`·`patch` 가운데 하나(3단계 1번 갈래)이거나 구체적인 버전 값(2번 갈래, 3번 갈래에서 사용자가 답한 값)이다. 넘길 인자가 없으면 아직 3단계가 끝나지 않은 것이므로 4단계로 오지 않는다.

같은 명령을 인자 없이 실행하면 3단계 3번 갈래의 후보 산출이 되며, 그 출력은 검증 결과가 아니다.

1단계 스크립트 끝의 두 `console.log` 줄을 아래로 바꾸고, 인자를 **`node -e '…' -- "{인자}"` 형태로** 넘겨 실행한다(3단계 3번 갈래의 후보 산출은 `-- "{인자}"` 없이 실행한다). 아래는 그 자리에 넣을 JavaScript 조각이며 셸에 그대로 붙여 실행하는 명령이 아니다.

```js
const SEMVER=/^(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$/;
if(pv!==xv)fail("두 원본의 현재 버전이 다릅니다 (package.json="+pv+", plugin.xml="+xv+"). 파일을 수정하지 않고 중단합니다");
if(!SEMVER.test(pv))fail("현재 버전 "+pv+"은(는) 안정 버전 SemVer M.m.p가 아닙니다. 두 파일의 현재 값을 먼저 바로잡으십시오");
const u=process.argv[1];
const n=pv.split(".").map(Number);
const cand={patch:[n[0],n[1],n[2]+1].join("."),minor:[n[0],n[1]+1,0].join("."),major:[n[0]+1,0,0].join(".")};
if(u===undefined){console.log("현재 버전: "+pv);console.log("patch\t"+cand.patch);console.log("minor\t"+cand.minor);console.log("major\t"+cand.major);process.exit(0);}
const next=Object.prototype.hasOwnProperty.call(cand,u)?cand[u]:u;
if(!SEMVER.test(next))fail("새 버전 "+next+"은(는) 안정 버전 SemVer M.m.p가 아닙니다");
const b=next.split(".").map(Number);
const cmp=(b[0]-n[0])||(b[1]-n[1])||(b[2]-n[2]);
if(!(cmp>0))fail("새 버전 "+next+"은(는) 현재 버전 "+pv+"보다 크지 않습니다");
console.log(next);
```

- **반드시 `node -e '…' -- "{인자}"` 형태로 실행한다.** 조합한 결과를 임시 파일에 저장해 `node 파일.js {인자}`로 돌리면 `process.argv[1]`이 인자가 아니라 그 스크립트 경로가 되어, 경로를 새 버전으로 읽고 "안정 버전 SemVer M.m.p가 아닙니다"라는 원인과 무관한 오류로 끝난다.
- 이 명령은 **현재 버전을 두 파일에서 스스로 다시 읽는다.** 앞 단계에서 읽은 값을 명령 문자열에 되붙이지 않으므로, 파일 내용이 명령으로 해석될 자리가 없다.
- 인자로 넘기는 것은 사용자나 호출자가 정한 단위·버전 값 하나뿐이다. **넘기기 전에 `^(major|minor|patch)$` 또는 `^(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$` 가운데 하나에 맞는지 확인한다.** 어느 쪽에도 맞지 않으면 명령에 넣지 말고 받은 값을 그대로 보고한 뒤 중단한다 — 무엇을 막을지 나열하는 대신 허용할 형태만 통과시킨다.
- **`--` 구분자를 빠뜨리지 않는다.** `node`는 `-e {스크립트}` 뒤에도 옵션 해석을 계속하므로, `-`로 시작하는 인자는 `process.argv[1]`에 닿지 않고 node 자신의 옵션으로 먹힌다. 예컨대 `--require=...`는 스크립트보다 먼저 실행되고 `process.argv[1]`은 `undefined`가 되어, 이 스킬이 후보 산출 갈래로 빠지면서 **종료 코드 0으로 끝난다**(node v22.14.0 실측). `-- "{인자}"`로 넘기면 그런 값도 그대로 `process.argv[1]`에 담겨 위 형식 검사에서 걸린다.
- 비교는 사전순이 아니라 **수치로** 한다 (`1.0.10`은 `1.0.9`보다 크다). `!(cmp>0)`으로 판정하므로 `cmp`가 `NaN`이어도 실패로 떨어진다.
- 하나라도 어긋나면 **파일을 수정하지 않고** 사유를 보고한 뒤 중단한다. 값을 추측해 고쳐 쓰지 않는다.
- 통과하면 출력의 **마지막 한 줄에 나온 단일 값**을 `{새버전}`으로 기록한다. 인자 없이 실행해 나온 여러 줄 후보 목록은 검증을 거치지 않은 출력이므로 `{새버전}`이 될 수 없다 — 그 출력을 받았다면 인자를 빠뜨린 것이므로 3단계로 돌아간다.

### 5. 두 파일 수정

검증을 통과한 경우에만 수정한다. **아래 두 값 외에는 아무것도 바꾸지 않는다.**

- `package.json`: 최상위 `version` 필드의 값 `{현재버전}` → `{새버전}`.
  - `"version": "{현재버전}"` 한 곳만 바꾼다. 파일 전체를 다시 직렬화하거나 들여쓰기·키 순서를 바꾸지 않는다.
  - `npm version`은 쓰지 않는다 — 태그를 만들고 lifecycle 스크립트를 돌린다.
- `plugin.xml`: 루트 `<plugin>` 여는 태그의 `version="{현재버전}"` → `version="{새버전}"`.
  - **실제 파일에 쓰인 따옴표 종류를 그대로 유지한다.** 1단계는 XML이 허용하는 큰따옴표와 작은따옴표를 모두 읽으므로, 이 파일이 `version='1.0.6'`으로 적혀 있으면 편집 대상도 작은따옴표 쪽이다. 따옴표를 바꾸지 않는다.
  - **1행의 XML 선언 `<?xml version="1.0" ... ?>`은 건드리지 않는다.** 이 파일에는 `version` 속성이 이미 두 군데 있으므로 "처음 나오는 `version=`"을 고치면 XML 선언이 깨진다. 루트 `<plugin>` 여는 태그 안의 것만 바꾼다.

수정은 실행 중인 에이전트의 파일 편집 수단으로 하며, 특정 도구 이름에 의존하지 않는다.

**편집 실패 처리**: 각 편집의 성공 여부를 그 자리에서 확인한다. 대상 문자열을 찾지 못했거나, 여러 곳에 매칭됐거나, 권한 오류로 쓰지 못했으면 **다음 파일로 넘어가지 말고 즉시 중단한다.** 중단할 때 **어느 파일이 이미 바뀌었고 어느 파일이 그대로인지 명시해 보고한다** — 두 파일 중 한쪽만 바뀐 상태는 이 저장소에서 릴리스를 깨뜨리므로 사용자가 알아야 한다. 이미 바꾼 값을 되돌리지는 않는다.

### 6. 검증

**이 단계부터는 파일이 이미 수정된 상태다.** 아래 어느 항에서 중단하든 그 사실을 함께 보고하며, 이미 바꾼 값을 되돌리지 않는다. 1단계의 "파일을 수정하지 않은 채 중단한다"는 여기에 적용되지 않는다.

1. 1단계와 같은 명령으로 두 값을 **다시 읽는다.**
   - **읽기 명령이 비정상 종료하면** 편집이 파일을 깨뜨렸을 수 있다(JSON 파싱 실패, `<plugin>` 여는 태그 손상 등). 어느 명령이 어떤 오류로 실패했는지 그대로 보고하고, **파일이 이미 수정된 상태임을 밝힌 뒤** 중단한다.
2. 두 값이 서로 같고 `{새버전}`과 정확히 일치하는지 확인한다. 어긋나면 어느 파일이 어떤 값인지 보고하고 중단한다 — 한쪽만 바뀐 상태를 그대로 두지 말고 사용자에게 알린다.
3. `git status --porcelain -- package.json plugin.xml`로 **두 파일이 모두 변경 상태로 잡히는지** 확인한다.
   - **양방향으로 본다.** 둘 중 하나라도 목록에 없으면 그 파일의 수정이 반영되지 않은 것이므로 보고하고 중단한다 — 초과분만 보면 부분 실패와 무수정 상태가 조용히 통과한다.
   - `git diff --name-only`를 쓰지 않는 것은 그 명령이 인덱스와 비교하기 때문이다. 에이전트나 훅이 파일을 스테이징하면 출력이 비어 실제 변경을 놓친다. `git status --porcelain`은 스테이징된 변경도 낸다.
   - 경로를 두 파일로 한정하는 것은, 스킬 실행 **전부터** 트리에 있던 무관한 변경이 목록에 섞여 거짓 경보를 내는 것을 막기 위해서다. 그 밖의 변경은 이 스킬의 관심사가 아니다.
4. `npm test`를 실행한다.
   - **종료 코드가 0이 아니면 이 스킬은 실패로 끝난다.** 실패 출력을 그대로 보고하고, 7단계 요약 **첫 줄에 실패를 명시하며**, 두 파일이 이미 새 버전으로 수정된 상태임을 함께 알린다. 이 스킬은 테스트 실패를 자동으로 고치지 않으며, 실패를 요약 표의 한 행으로만 적고 성공으로 마무리하지 않는다.

### 7. 요약

다음을 표로 보고한다.

- 이전 버전, 새 버전
- 수정한 파일 (`package.json`, `plugin.xml`)
- 두 원본의 값 일치 여부
- `npm test` 결과

## 하지 않는 것

이 스킬은 아래를 **수행하지 않는다.** 사용자가 별도로 요청하면 그때 다른 절차로 처리한다.

- `git commit`, `git tag`, `git push`
- `npm publish`
- GitHub release 생성
- CHANGELOG 작성
- Cordova CLI 버전 변경
- `cordova-ios`, `cordova-android` 등 플랫폼 버전 변경
- `package.json`의 `engines.cordovaDependencies` 변경
- 이 플러그인을 사용하는 상위 앱의 앱 버전 또는 빌드 번호 변경

## 중단 조건 요약

이 절이 중단 조건의 단일 참조점이다. **5단계 전후로 전제가 다르므로 두 묶음으로 나눈다.**

### 파일을 수정하지 않은 채 멈추는 조건 (1~4단계)

- `package.json`을 읽거나 파싱하지 못함 (1단계)
- `package.json`의 최상위 `version`이 없거나, `null`이거나, 빈 문자열이거나, 문자열이 아님 (1단계)
- `plugin.xml`을 읽지 못함 (1단계)
- `plugin.xml`에서 루트 `<plugin>` 여는 태그를 찾지 못함 (1단계)
- 루트 `<plugin>`에 `version` 속성이 없거나 그 값이 빈 문자열임 (1단계)
- 두 원본의 현재 버전이 서로 다름 (2단계)
- 현재 버전이 `M.m.p` 형식이 아님 (2단계)
- 새 버전이나 증가 단위를 받지 못했고 대화형 입력도 불가능함 (3단계)
- 새 버전이 `M.m.p` 형식이 아님 (4단계)
- 새 버전이 현재 버전보다 크지 않음 (4단계)
- 넘길 인자가 `major`·`minor`·`patch`도 `M.m.p`도 아님 (4단계)

### 파일이 이미 수정된 상태로 멈추는 조건 (5~6단계)

아래는 모두 **이미 바꾼 값을 되돌리지 않고**, 어느 파일이 어떤 상태인지 밝혀 보고한 뒤 멈춘다.

- 파일 편집 실패 — 대상 문자열 미발견, 다중 매칭, 권한 오류. **부분 수정 상태일 수 있다** (5단계)
- 재읽기 명령 자체의 비정상 종료 — 편집이 JSON이나 XML을 깨뜨렸을 수 있다 (6단계 1항)
- 재읽은 두 값이 서로 다르거나 `{새버전}`과 일치하지 않음 (6단계 2항)
- `package.json`과 `plugin.xml` 중 하나라도 변경 상태로 잡히지 않음 (6단계 3항)
- `npm test` 실패 — 두 파일은 새 버전으로 수정된 상태로 남는다 (6단계 4항)

## 이 스킬이 두 경로에 있는 이유

기준 구현은 `.claude/skills/version-up/SKILL.md` 하나뿐이다. `.agents/skills/version-up`은 그 디렉터리를 가리키는 저장소 상대 심볼릭 링크다. 사본을 두 벌 두지 않으므로 두 제품이 언제나 같은 절차를 실행한다. **이 스킬을 고칠 때는 `.claude/skills/version-up/SKILL.md`만 고친다.**

두 탐색 경로의 근거는 각 제품의 공식 문서이며, **아래는 2026-08-26 확인 시점의 동작이다.** 두 제품 모두 외부 도구이므로 탐색 경로와 심볼릭 링크 처리는 바뀔 수 있다. 링크가 해석되지 않으면 이 절을 근거로 삼지 말고 해당 제품의 최신 문서를 다시 확인한다.

| 제품 | 탐색 경로 | 심볼릭 링크 | 명시 호출 |
|---|---|---|---|
| Claude Code | `.claude/skills/<이름>/SKILL.md` | `<이름>` 항목이 링크면 대상의 `SKILL.md`를 읽는다 | `/version-up` |
| Codex | `$REPO_ROOT/.agents/skills` | 링크된 스킬 폴더의 대상을 따라간다 | `$version-up` |

- Claude Code: [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- Codex: [Build skills](https://learn.chatgpt.com/docs/build-skills)

**[미확인]** 이 저장소에서 Codex가 실제로 링크를 따라 이 스킬을 발견하는지는 사용하는 Codex 버전에 따라 다를 수 있다. `.agents/skills` **디렉터리 자체**를 링크로 두면 발견되지 않는다는 보고가 있으나(openai/codex#11314, `not planned`로 종료), 이 저장소는 하위 항목만 링크하므로 공식 문서가 지원한다고 적은 범위에 해당한다.

이 표가 두 경로에 관한 유일한 기재다. `README.md`는 이 절을 가리키기만 하고 같은 내용을 옮겨 적지 않는다 — 두 곳에 적으면 한쪽만 고쳐져 어긋난다.
